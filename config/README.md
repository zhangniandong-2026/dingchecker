# 业务单元配置说明

## 配置文件

`business_units.txt` - 业务单元列表配置

## 使用方法

### 1. 添加新业务单元

编辑 `business_units.txt` 文件，每行添加一个单元名称：

```bash
# 编辑配置文件
nano ~/dingtalk_checker/config/business_units.txt

# 或者直接追加
echo "新业务单元名称" >> ~/dingtalk_checker/config/business_units.txt
```

### 2. 单元名称要求

- 必须与钉钉文档中的工作表名称**完全一致**
- 区分大小写
- 不能有多余的空格

### 3. 注释和分组

支持使用 `#` 添加注释和分组：

```txt
# 政府行业
政府行业一组
政府行业二组

# 重点行业
交通行业组
能源组
```

### 4. 验证配置

运行检查脚本时会显示加载的单元数量：

```bash
python3 ~/dingtalk_checker/scripts/daily_check.py

# 输出示例：
# ✓ 从配置文件加载了 10 个业务单元
```

### 5. 向后兼容

- 如果配置文件不存在，自动使用默认的 6 个单元
- 如果配置文件为空或读取失败，也使用默认单元
- 保证系统稳定性

## 常见问题

### Q1: 添加新单元后没有生效？

确认：
1. 单元名称是否与钉钉文档完全一致
2. 文件编码是否为 UTF-8
3. 没有多余的空格或特殊字符

### Q2: 可以临时禁用某个单元吗？

可以，在单元名称前加 `#` 注释掉：

```txt
媒体军工组
# 交通行业组  # 临时禁用
政府行业一组
```

### Q3: 支持多少个单元？

理论上无限制，但建议：
- 10 个以内：运行速度快
- 10-20 个：正常运行
- 20-50 个：需要更多时间
- 50 个以上：考虑分批检查

### Q4: 可以修改单元检查顺序吗？

可以，配置文件中的顺序就是检查顺序。把重要的单元放在前面。

### Q5: 如何恢复默认配置？

删除或重命名配置文件：

```bash
mv ~/dingtalk_checker/config/business_units.txt ~/dingtalk_checker/config/business_units.txt.backup
```

系统会自动使用默认的 6 个单元。

## 维护建议

1. **定期审查**：每月检查一次配置，删除不再需要的单元
2. **备份配置**：重要配置可以备份
3. **版本控制**：如果使用 git，可以追踪配置变更
4. **命名规范**：建议统一单元命名格式

## 技术细节

- 配置文件路径：`~/dingtalk_checker/config/business_units.txt`
- 文件编码：UTF-8
- 每行一个单元
- 支持 `#` 注释
- 自动跳过空行
- 加载失败时使用默认配置（向后兼容）
