# 业务单元每日晨会规范与评分标准

**版本**: v4.0  
**更新日期**: 2026-04-30  
**适用对象**: 各业务单元销售、售前及负责人

---

## 一、会议基本规范

### 1.1 时间控制
- **会议时长**: 15-30 分钟（根据参会人数调整，人均 2-3 分钟）
- **开始时间**: 建议 08:30-09:00，各单元可自行确定
- **准时原则**: 到点就开，迟到者自行补齐信息

### 1.2 录音规范
- **必须开启钉钉AI听记**，确保转写质量
- 发言时说清客户全名（避免"那个客户"、"他们"等代词）
- 禁止同时多人说话（影响转写识别）

### 1.3 参会要求
- 销售/售前/负责人全员参加
- 禁止代为传达（"XX今天请假，他说..."）
- 无进展也要发言（说"无新进展，今日XX"）

---

## 二、汇报"3段式"结构

每人按以下顺序发言，控制在 2 分钟内：

### 📊 第一段：昨日战果

**必须包含的要素**：
```
客户名 + 动作 + 结果 + 数据
```

**✅ 好的示例**：
- "辽宁联通主机安全项目，昨天完成需求确认，预计30万，今天提交初步方案"
- "费泰16款APP，客户已确认合同，回款4万预计本周到账"

**❌ 不合格示例**：
- "昨天跟进了几个项目"（无客户名、无结果）
- "联系了客户"（无动作结果、无数据）
- "推进顺利"（无具体内容）

---

### 📋 第二段：今日计划

**必须包含的要素**：
```
客户名 + 具体动作 + deadline
```

**✅ 好的示例**：
- "辽宁电信，今天下午2点前提交技术方案"
- "沈阳兴业银行维保，今天联系采购部确认预算，争取本周下单"

**❌ 不合格示例**：
- "今天继续跟进"（无具体动作）
- "推进几个项目"（无客户名）
- "看情况"（无计划性）

---

### 🤝 第三段：协同需求

**必须包含的要素**：
```
需要谁 + 什么时间 + 支持什么
```

**✅ 好的示例**：
- "需要售前小李，今天上午出一版联通主机安全的技术方案"
- "需要总部确认折扣权限，今天中午前给回复，否则影响下午投标"

**❌ 不合格示例**：
- "可能需要支持"（不明确）
- "看看谁有空帮忙"（无责任人）

**无需求时**：直接说"无协同需求"（不要跳过）

## 三、负责人点评规范

### 3.1 "四不四要"原则

**四不**：
1. **不超过会议时长的 30%**（否则变成独角戏）
2. **不低于 20%**（否则缺乏指导）
3. **不用"嗯嗯"糊弄**（要有实质决策）
4. **不讨论技术细节**（会后开专项会解决）

**四要**：
1. **要现场响应协同需求**（不能都说"会后对接"）
2. **要指出卡点并给资源**（不能只夸不帮）
3. **要做进度提醒**（Q1/Q2/Q3/Q4目标完成度）
4. **要控制失控者**（单人超2分钟强制打断）

### 3.2 高效点评模板

```
[判断] + [动作] + [deadline]
```

**✅ 好的示例**：
- "联通项目进展OK，小李今天下午必须出方案，否则影响明天投标"
- "费泰合同拖太久，今天让客户发书面确认邮件，别等了"
- "维保项目集中在Q1末，大家加速，本周必须全部下单"

**❌ 不合格示例**：
- "嗯嗯，好，继续"（无实质内容）
- "大家加油"（无具体指导）
- "这个事情比较复杂..."（讨论超时）

## 四、纪律红线（自动检测）

系统会自动检测以下违规情况：

| 红线 | 标准 | 处理 |
|------|------|------|
| **单人超时** | >2 分钟 | 报告中标记，主持人应打断 |
| **发言失衡** | 前3人占比 >70% | 报告中预警，关注沉默者 |
| **管理者失位** | 发言占比 <10% 或 >50% | 报告中标记异常 |
| **空洞汇报** | 无客户名、无数据、无动作 | 维度评分降低 |

## 五、四维度评分标准（总分20分）

### 维度1：昨日战果 (1-5分)

**评分依据**：
- ✅ **5分**：每人至少1个具体战果 + 客户名 + 结果 + 数据（金额/阶段/数量）
- ✅ **4分**：多数人有具体战果，但缺少量化数据
- ✅ **3分**：有战果汇报但不具体（"跟进了"、"推进中"）
- ⚠️ **2分**：少数人汇报战果，多数人直接说今天计划
- ❌ **1分**：几乎无战果汇报，开会就是派任务

**量化指标**（系统自动检测）：
- 包含"签约"/"确认"/"交付"/"金额"/"完成"等关键词的段落占比
- 发言中数字出现频率（金额、百分比、数量、阶段进度）
- 客户全名出现频率（"XX公司" vs "那个客户"）

**扣分点**：
- "昨天请假了"（无战果）
- "继续推进"（无具体进展）
- "客户还在考虑"（无动作结果）

---

### 维度2：今日计划 (1-5分)

**评分依据**：
- ✅ **5分**：每人1-3个核心任务 + 客户名 + 具体动作 + deadline
- ✅ **4分**：任务清晰但缺少时间节点
- ✅ **3分**：任务清晰，但有轻微啰嗦或发散
- ⚠️ **2分**：任务模糊（"今天继续跟进"）
- ❌ **1分**：无计划或大量时间讨论流程问题

**量化指标**（系统自动检测）：
- 平均发言段落数/人（<10段聚焦，>20段啰嗦）
- 是否出现"还有啥？"、"想不起来了"等准备不足信号
- 任务数量是否合理（1-3个为佳，>5个可能过载）
- 时间词出现频率（"今天"/"上午"/"下午"/"本周"）

**扣分点**：
- 任务过多过细（"今天要打10个电话、发5封邮件..."）
- 任务过于宏观（"推进Q1目标"）
- 发言时自己也不清楚要做什么

---

### 维度3：协同效率 (1-5分)

**评分依据**：
- ✅ **5分**：管理者对每个协同需求现场响应 + 明确时间/责任人 + 协同方（售前/交付）主动反馈可行性
- ✅ **4分**：多数协同需求得到响应，少数"会后对接"，协同方有基本反馈
- ✅ **3分**：协同需求有记录，但管理者多为"嗯嗯"确认，协同方被动响应或无反馈
- ⚠️ **2分**：协同需求被忽略或延后，无人响应，协同方沉默
- ❌ **1分**：无协同讨论，或讨论超时失控

**量化指标**（系统自动检测）：
- 管理者短促确认语（"嗯"/"好"/"OK"）占总发言段落比例
  - <30%：有实质点评
  - 30-50%：一般
  - >50%：效率低下
- 协同需求响应速度（从提出到回复的段落间隔）
- 跨人对话轮次（多轮对话说明协同频繁）
- **协同方（售前/交付）响应次数**（被点名后是否主动反馈"可以"/"有困难"/"需要XX时间"）

**扣分点**：
- 管理者对协同需求全是"嗯嗯"、"好"
- 协同需求提出后无人响应
- **协同方被点名后沉默，未给反馈**（如："小李你今天能出方案吗？" → 小李无回应）
- 讨论技术细节超过3分钟

---

### 维度4：点评效率 (1-5分)

**评分依据**：
- ✅ **5分**：管理者点评精准有力 + 每人至少1条指导 + 发言时长占比 20-30%
- ✅ **4分**：有战略指导，但占比偏低（<20%）或偏高（30-40%）
- ✅ **3分**：多为信息确认，少量实质指导
- ⚠️ **2分**：几乎无点评，或点评跑题
- ❌ **1分**：管理者缺席或沉默（<10%）

**量化指标**（系统自动检测，这是v4核心优势）：
- 管理者发言时长占比
  - 20-30%：理想区间（5分）
  - 15-20% 或 30-40%：一般（4分）
  - 10-15% 或 40-50%：偏离（3分）
  - <10% 或 >50%：异常（1-2分）
- 管理者平均段落长度（区分"短促确认" vs "实质点评"）
- 管理者主动提问次数（"XX项目到哪了？"）
- 决策性语句数量（"今天必须"/"立即"/"我要求"/"不行"）

**扣分点**：
- 管理者全程"嗯嗯嗯"（<10%时长）
- 管理者独角戏（>50%时长）
- 无任何决策性指导

## 六、评分等级说明

| 总分 | 等级 | 评价 |
|------|------|------|
| 18-20 | 优秀 | 组织有序，执行有力，管理到位 |
| 15-17 | 良好 | 整体合格，个别维度需加强 |
| 12-14 | 及格 | 基本达标，但存在明显短板 |
| 9-11  | 需改进 | 多个维度不合格，需要整改 |
| <9    | 不合格 | 早会形式化严重或管理失控 |

## 七、常见问题

### Q1：如果今天确实无新进展怎么办？
**A**: 说清楚原因和下一步动作。
- ❌ 错误："无进展"（就结束了）
- ✅ 正确："XX项目昨天客户未回复，今天上午10点前再次跟进，若无回复则升级到客户领导"

### Q2：如果今天任务很多怎么办？
**A**: 只说最重要的1-3个，其他的写在个人待办里。
- 早会不是任务清单朗读会
- 只说影响Q1目标/本周关键里程碑的任务

### Q3：负责人发言占比30%是否太少？
**A**: 早会是执行层汇报，不是战略会。
- 负责人20-30%用于：确认信息、指出卡点、分配资源、做决策
- 如需深入讨论，说"这个事下午2点单独开会"

### Q4：系统检测到超2分钟，是否一定扣分？
**A**: 不一定，看内容密度。
- 如果2分钟里都是实质内容（多客户进展、复杂协同）→ 不扣分
- 如果2分钟里有大量"嗯"、"然后"、重复 → 扣分

### Q5：没有协同需求也要说吗？
**A**: 是的，说"无协同需求"（1秒钟的事）。
- 避免管理者追问："你需要支持吗？"（浪费时间）
- 明确表态后，管理者可直接进入下一人

## 八、检查清单（会后自查）

**每周五回顾本周早会质量**：

- [ ] 时长是否控制在30分钟内？
- [ ] 是否有人单次发言超3分钟？
- [ ] 是否每人都汇报了昨日战果？
- [ ] 是否每人的今日计划都有deadline？
- [ ] 管理者是否对协同需求现场响应？
- [ ] 管理者发言占比是否在20-30%？
- [ ] 是否讨论了与当日执行无关的话题？

**如果3项以上为"否"，下周需要调整。**

## 九、本规范的特点

✅ **基于真实转写数据**：所有量化指标均可通过系统自动检测  
✅ **避免形式化**：不要求背模板，只要求说清楚  
✅ **聚焦执行**：昨日-今日-协同，不讨论战略  
✅ **管理可控**：红线清晰，超时/失衡/失位均可量化
